Handoff: Admit Day — saved list (/my-schools)

Overview

The screen behind the saved count in the header. A family lands here after adding schools from /find or a school detail page, and it answers three questions and only three:

  1. What's on my list, and in what order?
  2. What does that list look like as a whole?
  3. Can I get it out of here?

Everything else was deliberately removed. Requirements and deadlines live on /checklist, not here — this page is about the list itself.

Rank order is the product. NYC families submit an ordered list of programs in MySchools; the ranking on this page is a draft of that submission. So the ranking table is the page's spine, and the reorder control is treated as a primary control, not a nicety.

The list is generated, not just collected. Schools arrive here because they matched the family's selection criteria on /find. There is no cap on length — counselors advise ranking twelve or more, but the design never counts down to a target or nags. No "3 of 12 slots used", no progress bar, no completion badge.

Target codebase: Next.js 14 App Router + React + Tailwind, tokens already in tailwind.config.ts from the /find handoff.

About the design files

saved-list.html is a design reference created in HTML — intended look and layout, not production code. Recreate it with the codebase's Tailwind tokens and App Router patterns; don't paste the markup in. All schools, ratios and dates are placeholder.

Fidelity: high. Colors, type, spacing and layout are final. Interactions are indicated, not implemented.

6b is the approved direction. 6a and 6c are the same layout in two other data conditions — build one component that produces all three.

Inherited system — unchanged

Radius 0 everywhere. No shadows. Separation by 1px rules, never cards. One accent: #1D4ED8.

Tokens: ink #0B0B0C, ink-2 #2A2A2F, muted #55555A, faint #8A8A90, rule #E8E8E4, rule-light #F0F0EC, border #DEDEDA, surface #FFFFFF, surface-2 #FAFAF8, accent #1D4ED8, accent-bg #EEF2FF, accent-border #C7D2FE.

Three faces, three jobs — Space Grotesk 700 for the page title (My Schools) and the Admit wordmark only; Libre Franklin for everything read; JetBrains Mono for every number, code, date and uppercase eyebrow; Newsreader italic 500 for the Day in the wordmark only.

1120px max width. Same header. Nav is Find / My Schools + mono saved count in accent / Checklist — note the rename from Readiness; it applies across all screens.

Design decisions (and why)

Reordering is explicit controls, with drag as a shortcut

Each row carries a mono rank numeral and a pair of 26px ↑ / ↓ buttons; the whole row is also draggable via a ⠿ handle. Drag alone was rejected for three reasons: this list can run to 14+ rows so drag means scroll-drag, the audience skews toward parents on phones and shared/older machines, and rank order is the one thing on the page that must be verifiable — a parent needs to see 07 and know it is seventh, then move it one place with certainty.

The ↑ on the first row and ↓ on the last are rendered in border grey (disabled), never hidden — the control's shape stays constant down the column.

Rank numerals are positional, not stored. They re-render 01…N after every move. Never show a stale number.

Composition is a proportion band plus counts. It is never a score.

A 12px-tall band of flex-weighted segments in four greys (ink → ink-2 → muted → faint), followed by a legend of swatch · label · mono count. Greyscale is deliberate: color would encode good/bad. Nothing is ordered by desirability, nothing is labelled "risky", "safe", "reach" or "balanced", and no percentage is shown — a percentage invites a target.

The segment weights must be derived from the same counts as the legend. They encoded a different set in an early build and it read as three open/zoned schools where there were two — precisely the misread this section exists to prevent. One function, one source.

Track buckets are mutually exclusive and priority-ordered, because DOE programs carry several methods at once (Screened, Audition). Resolve in this order: SHSAT → Audition / Portfolio → Screened → Open / Zoned. A program is counted once, in its most selective bucket. The buckets must sum to the saved total — assert this in a test.

A zero-count bucket stays in the legend with a hollow swatch (1px border on surface) and faint text. This is the point of the section: a family with no open or zoned option needs to see Open / Zoned 0, and it cannot be seen if the row is dropped.

Below the legend, one factual sentence under a mono READING THE SHAPE eyebrow — generated from the counts, describing only what is there ("Every school on the list screens or tests. No open or zoned program is on it yet."). Never advisory, never predictive. The page footer carries the standing disclaimer: "Counts only — we don't score a list or predict an outcome."

Boroughs and applicants-per-seat get the same treatment as /school's stats grid: a 3-up cell grid, gap: 1px on a rule background, mono number over an uppercase label. Number first, label second — the digit is the content.

Requirements are not on this page

They were designed here and cut. Deadlines belong to /checklist, and a family looking at both saw the same three dates twice. Nothing on /my-schools links to it except the nav item. When /checklist is designed, it reads the same saved set.

Export is one primary button in the header

Labelled just Export — ink fill, white, 11px 20px, top right of the title band. It was originally a rail card with explanatory copy and a PDF label; both were removed. Export is the growth mechanic, so it gets the page's only filled button and no competition. Share-link is deliberately deferred — the design has room for it as a second button in the same cluster.

The export itself is the ranked list in order with each program's DBN: the sheet a parent keeps open while typing into MySchools. Rules-and-rows on white prints cleanly, which is why the layout was built this way.

The match strip is borrowed content and is labelled as such

6a carries a 3-up strip under the eyebrow FROM YOUR 31 MATCHES ON FIND, with an Open in Find ↗ link. It is the /find result set for the saved criteria, re-run and de-duplicated against the list — nothing new is computed here, and /find stays the source of truth. Each card names why it matched in accent text.

Show it below 6 saved; drop it above. Once the list is long, re-showing search results competes with the ranking, and the nav handles it from there.

Layout

1. Header — 18px 36px, border-bottom: 1px rule

As /find, with Checklist as the third nav item and the mono saved count on My Schools.

2. Title band — grid 1fr auto, align-items: end, 30px 36px 24px, border-bottom: 1px rule

Left: My Schools (Space Grotesk 700, 40px, lh 1.04, ls −0.038em). Right: the Export button. No subtitle, no count line — the nav count and the table's own numerals carry that.

3. Selection criteria strip — 11px 36px, surface-2, border-bottom: 1px rule

Mono uppercase SELECTION CRITERIA label, then one accent chip per criterion (12.5px, accent-bg, 1px accent-border, 5px 9px), then a right-aligned Edit criteria link back to /find with those filters applied. Same chip treatment as the ask chips on /find — same mechanic, so the same styling. Omit the strip when a list was built without criteria.

4. Body — grid 1fr 316px, main column border-right: 1px solid rule

316px matches the /find filter rail and the /school info rail, so all three screens share a spine.

Main column — the ranking (26px 36px 30px). Eyebrow row: YOUR RANKING left, and right, 12.5px faint: "Drag a row, or use ↑ ↓" — on the wider single-column states the sentence extends to "— this order is the one you'll enter in MySchools."

Table is a set of grid rows, not a <table>. Column template at 14 rows (1fr main column): 46px 1fr 132px 62px 74px, gap 12px, 11px 0, border-bottom: 1px rule-light. At full width (6a, 6c, single-column states) it opens up to 54px 1fr 156px 112px 96px, gap 16px, 15px 0, and the remove control becomes the word Remove instead of ×.

Header row: mono 10px uppercase, ls .1em, faint — Rank / School & Program / Track / A/Seat, plus an empty cell for controls. border-bottom: 1px rule.

Each row:
1. ⠿ drag handle (13px, border grey; faint on hover) + mono rank numeral (16px, weight 500, ink).
2. School name as a link to /school/[dbn] (15px/600 ink) over a 12.5px muted line: Program · Neighborhood, Borough. At full width the DBN sits in that line in mono.
3. Track (13.5px ink-2) — the program's methods as published, comma-separated. This is the raw string; the composition buckets are a separate derivation.
4. Applicants per seat, mono 14px ink.
5. ↑ ↓ (23px square at 14 rows, 26px at full width, 1px border) + remove.

Hovered/dragging row takes surface-2 and its controls darken to 1px muted.

Rail — two stacked sections divided by border-bottom: 1px rule:

  • Composition (26px 28px) — eyebrow with a right-aligned mono 14 SAVED; the band; the legend as full-width rows (swatch · label · flex:1 · mono count); then the Boroughs and Applicants-Per-Seat cell grids, each under its own mono label, separated by border-top: 1px rule-light and 14px padding.
  • Last edited (20px 28px) — mono LAST EDITED label + a 13px line naming the change (Jul 28, 2026 · moved Beacon to 3). Small, but it is the only confirmation that a reorder persisted.

5. Footer band — 16px 36px, surface-2, border-top: 1px rule

Two 13px faint lines, spread apart: left "DOE-published data for the 2026–27 cycle · confirm each program on the official listing before you apply"; right, right-aligned, "Counts only — we don't score a list or predict an outcome."

States

Empty (never saved anything). Not in the reference — it was designed, reviewed and cut, and it should be built as the simplest possible version: keep the header and title band, then one line stating nothing is saved and a single accent link to /find. Do not build an onboarding panel, a three-fact explainer or a three-up "start somewhere" grid; that was the rejected version. A parent who lands here by accident needs one door, not a tour.

1–3 saved (6a). Full-width single-column layout — no rail. Order: ranking → composition → match strip. The ranking is short, so composition sits below it rather than beside it, and the match strip carries the bottom of the page.

Long list (6b, the approved direction). Two columns from the criteria strip down. Ranking left, composition + last-edited right. No match strip. Applies at 7+ saved; there is no upper bound.

Thin data (6c). A school with no published applicants-per-seat renders mono uppercase NOT REPORTED in faint in that cell — never —, never 0. Immediately below the row, spanning the content columns, a mono DATA GAP eyebrow + 13px muted sentence: "The DOE doesn't publish an applicants-per-seat figure for this school. That's a gap in the source data, not a low number." The final clause is required. The READING THE SHAPE line also notes that the column is incomplete for this list, so the family isn't comparing against a partial set unknowingly.

Reorder. Optimistic and immediate: renumber, then persist. On failure, revert to the previous order and show one 13px line under the table — never a toast that can be missed while the parent is reading the list. ↑/↓ must be keyboard-operable and announce the new position.

Remove. Optimistic; row leaves, list renumbers, header count decrements in the same tick. No confirmation dialog — instead, hold an undo affordance for ~10s in the same 13px line slot below the table. The list is a draft; a modal per removal is the wrong weight.

Export pending. Button takes a disabled state with the label unchanged; a mono status line appears in the footer band. Never a spinner overlay.

Hover. Rows and rail links take surface-2. Buttons invert to ink fill / white. Transitions 120ms ease-out. No transforms, no lift.

Focus. 2px accent outline, 2px offset, on every interactive element including the drag handle. The rank cell must be reachable by keyboard.

Responsive (below ~900px)

  • The 1120px layout reflows; it never compresses. Single column below 900px.
  • The 316px rail moves below the ranking, in order: Composition → Last edited. It drops border-right and keeps its own 1px rule dividers.
  • The ranking table collapses to a two-line row, not a scrolling table. Line one: drag handle + rank numeral + school name, with ↑ ↓ and remove right-aligned. Line two, indented to the name: Program · Neighborhood, then Track and the mono ratio separated by ·. Nothing scrolls horizontally.
  • Reorder controls grow to 44px hit targets at ≤700px. They stay side by side, right-aligned.
  • Composition band stays full width. The legend goes two-up. Borough and applicants-per-seat cell grids stay 3-up (they are narrow) and become 1-up only at ≤420px.
  • Criteria strip wraps to two lines: label + chips, then Edit criteria on its own line.
  • Export stays in the title band, full width beneath the title at ≤520px.
  • Footer disclaimers stack, left-aligned, 4px gap.
  • Title drops to 30px at ≤700px. Horizontal padding 36px → 20px.

Data shape

type SavedList = {
  criteria: { id: string; label: string }[];   // from the /find query that built this list
  items: SavedItem[];                           // stored in rank order — the array IS the ranking
  lastEditedAt: string;
  lastEditedSummary?: string;                   // "moved Beacon to 3"
};

type SavedItem = {
  dbn: string; name: string; program: string;
  neighborhood?: string; borough: string;
  methods: string[];                            // as published: ['Screened','Audition']
  applicantsPerSeat?: number;                   // absent → NOT REPORTED + data-gap line
};

Derive on the server:

type Composition = {
  total: number;
  buckets: { key: 'shsat'|'audition'|'screened'|'open'; label: string; count: number }[]; // zeroes kept
  byBorough: { label: string; count: number }[];
  byRatio:   { label: string; count: number }[];   // Under 3 / 3 to 6 / Over 6
  shapeSentence: string;                            // generated from buckets
  ratioMissing: number;                             // drives the incomplete-column note
};

buckets drives both the band weights and the legend — one array, no second source. Assert sum(buckets) === total.

New primitives

On top of /find's five (Chip, SegmentedControl, Button, StatBlock, SchoolRow) and /school's four (StatGrid, Eyebrow, DefinitionRow, NotReportedLine):

  • RankRow — one saved school; owns the handle, numeral, ↑ ↓, remove, and the two-line mobile collapse.
  • ProportionBand — takes Composition.buckets, renders weighted segments + legend, keeps zero buckets.
  • BreakdownCells — the 3-up mono-number cell grid (a StatGrid variant; consider merging with a size prop).

NotReportedLine is reused as-is for the data-gap line.
